# Whole-Simulator Audit Preparation Pack V1

Date: 2026-07-18

## Purpose

The full whole-simulator alignment audit should wait until every active node
build has reached a stable checkpoint. Auditing moving targets would mix real
product problems with work that simply is not finished yet.

This pack prepares the standards and evidence needed for that later audit
without changing active node code.

## Current North Star

The Hearth Mastery is one connected guitar-learning world.

- The Map shows where the learner can go.
- Journey recommends what the learner should do next.
- Nodes provide distinct places to learn, train, practise, study, play,
  create, reflect, and encounter mastery.
- The active learner profile owns the memory of what happened.
- Activity inside and outside formal lessons should update the same evidence.
- Final click destinations should lead to meaningful learning or musical
  action, not a dead-end text card.

## Next Safe Documents

The current handover set is complete. The next safe documents should come from
the final audit rather than another speculative planning pass:

1. verified click-path, ownership, storage, and evidence matrices;
2. one whole-product findings and implementation roadmap;
3. fresh post-audit continuation briefs for every node and Journey, following
   `post-audit-node-continuation-brief-standard-v1.md`.

## When The Final Audit May Begin

The comprehensive audit is ready to run when:

- every current node owner says its active build is at a stable checkpoint;
- current Foundation, Do, Know, and Journey status is recorded in the
  remaining-work index;
- each node has completed the Concept, Interaction, and Learning gates in the
  Node Definition of Done;
- incomplete features are labelled honestly rather than presented as done;
- the active branch passes the shared smoke and regression checks;
- the Decision Register has no unresolved question that changes the meaning or
  ownership of a node.

The final audit may still find problems. Readiness only means the product is
stable enough to judge fairly.

## Change Rule

Historical briefs remain evidence of the design process. Do not rewrite them
to make the history look cleaner. Record the current decision here, mark the
older direction as superseded, and link to the reason.
