# Book Library Workflow

The PDF library should become the source library behind The Hearth Mastery.

The aim is not to copy books into the app. The aim is to let the books guide the knowledge base while the simulator speaks in its own voice.

## Guiding Principle

The books are the knowledge source.

The Hearth is the teaching voice.

That means every lesson, drill, explanation, and roadmap item can be shaped by books, but the final student-facing content should be original, clear, and appropriate to the app.

## Copyright-Safe Use

Use books for:

- concepts
- chapter structures
- exercise ideas
- terminology
- page references
- short notes
- summaries
- comparison between sources

Avoid:

- storing long copied passages
- reproducing full chapters
- exposing copyrighted PDF text in the public app
- treating one author's exact wording as app content

The database should store references and original summaries, not cloned book text.

## Processing Order

Start with:

1. Teaching methodology books
2. Beginner guitar foundations
3. Practice technique
4. Rhythm
5. Chords
6. Fretboard and theory
7. Ear training
8. Improvisation and creation
9. Advanced style paths

This order matches the current need: first build the teaching philosophy, then the beginner roadmap.

## Book Intake Steps

For each PDF:

1. Add it to the book catalogue.
2. Identify whether the text is selectable or scanned.
3. Extract title, author, publisher/year if available.
4. Extract table of contents.
5. Assign primary skill nodes.
6. Assign level range.
7. Write a short "why this matters" note.
8. Identify chapters worth processing first.
9. Create source notes linked to roadmap items.
10. Convert useful ideas into original Hearth-style content.

## Book Catalogue Fields

Minimum fields:

- title
- author
- format
- file location
- text quality: selectable, scanned, mixed, unknown
- topic category
- skill nodes
- level range
- public reference allowed: yes/no
- openable in private library: yes/no
- notes

## Source Notes

Source notes are the bridge between a book and the app.

Each source note should capture:

- book
- chapter or section
- page range if available
- concept
- short summary
- useful quote marker if there is a small quote to revisit privately
- related roadmap item
- related TeachingEngine lesson
- how it should influence app content

## Public App vs Private Library

Some books may be openable inside a private reference library for Ayla.

That is different from making the book public inside the simulator.

Recommended split:

- Public app: original lesson content, short references, citations, resource names.
- Private library: local PDF access, reading notes, page references, source summaries.

## Processing Batches

Process books in batches of 3-5.

For each batch, produce:

- catalogue rows
- table of contents summary
- key concepts
- recommended roadmap links
- lesson/drill opportunities
- questions for Ayla

Avoid processing all 60 at once. The library should become intelligent, not just large.

## First Batch Recommendation

Start with teaching and learning method books.

Ideal first batch:

- one book about how to practise guitar
- one book about teaching or learning
- one beginner guitar method
- one music theory foundation book
- one ear/listening or musicianship book

This gives the knowledge base a spine: how to teach, what to teach first, and how to know whether learning is happening.
