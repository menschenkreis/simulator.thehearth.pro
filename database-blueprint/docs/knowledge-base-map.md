# Knowledge Base Map

## Plain-English Model

Think of the database as five connected libraries.

## 1. The Learning Map

This is the skeleton of The Hearth Mastery.

It answers:

- What are the major learning areas?
- What order should they appear in?
- What level is the student currently working at?
- What proves they are ready to move forward?

Core records:

- Nodes: Foundation, Doing, Knowing, Practice, Study, Create, Hearth, Mastery
- Skill nodes: Rhythm, Chords, Fretboard, Technique, Theory, Ear Training, Scales & Lead, Songs, Improvisation / Creation
- Levels: Level 1 through Level 8
- Roadmap stages: Initiation through Performance
- Lessons or learning units
- Pass conditions

Foundation should be treated as the threshold into this map. It should introduce the nodes, the learning method, the music-as-language metaphor, the first physical guitar actions, and the source-backed way the simulator explains things.

The node interiors should be modelled by scene type:

- Foundation: hybrid scene plus TeachingEngine
- Doing: fretboard grid
- Knowing: bookshelf and reader
- Practice: temple session system
- Study: concept/review chamber
- Create: cauldron prompt engine
- Hearth: brain progress map
- Mastery: inspiration chamber

## 2. The Teaching Library

This is the character-driven lesson content.

It answers:

- What does the guide say?
- What question does the learner answer?
- What happens if they answer incorrectly?
- What action should they physically try?

Core records:

- Lessons
- Lesson steps
- Speak steps
- Ask steps
- Cards
- Actions
- Gradient failsafe explanations

Important principle:

The TeachingEngine is worth keeping. The database should eventually feed it lesson steps rather than having every lesson hardcoded in JavaScript.

## 3. The Practice Library

This is the doing-and-repetition layer.

It answers:

- What should the student physically practise?
- How long?
- At what tempo?
- What counts as clean enough?
- What should they notice in the body?

Core records:

- Drills
- Practice sessions
- Timers
- BPM targets
- Confidence ratings
- Difficulty ratings
- Reflections
- Next action

Important principle:

Practice should not become punishment. It should stay embodied: tension, breath, clean notes, curiosity.

## 4. The Resource Library

This is the curated external knowledge layer.

It answers:

- Which YouTube video, course, article, book, or PDF supports this topic?
- Is it approved or only a candidate?
- What is it best for?
- Which level and node does it belong to?

Core records:

- Resource name
- Creator/platform
- Resource type
- URL
- Skill node
- Level
- Quality notes
- Status

Important principle:

Resources should be curated, not dumped. A link is only useful if the app knows why it is there.

## 5. The Creative Library

This is the Create node: obstructions, combos, dares, and composition prompts.

It answers:

- What creative constraint should the student face?
- Which ingredients are involved: lyrics, melody, riff, rhythm, story?
- What emotional or musical risk does it force?
- What revelation might it produce?

Core records:

- Obstructions
- Combos
- Ingredients
- Level
- Constraint
- Prompt
- Payoff

Important principle:

The Create node should feel alive, not like a worksheet. It should provoke, expose, and unlock.

## The Student Memory Layer

This comes after the content model.

It answers:

- Who is practising?
- What have they completed?
- What did they struggle with?
- What should happen next?
- What is their personal songbook?

Core records:

- Users
- Students/profiles
- Progress
- Practice logs
- Lesson attempts
- Notes
- Songbook entries

Important principle:

Progress is not just completion. It is memory: what stuck, what slipped, what needs returning to.
