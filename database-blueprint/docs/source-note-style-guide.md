# Source Note Style Guide

## Recommendation

Use a hybrid source-note system.

Do not choose between "one note per chapter" and "one note per tiny exercise."

Use both:

1. **Chapter anchor notes** - one broad note for each chapter or major section.
2. **Concept/exercise notes** - smaller notes only when the idea is useful for roadmap, lesson, drill, or app design.

## Why

Chapter notes give orientation.

Concept notes give usable building blocks.

If every paragraph becomes a note, the database becomes noisy.

If every chapter becomes only one note, the app loses the useful details.

## Voice

Use a semi-Hearth voice while staying source-traceable.

That means:

- clear enough for Martin/database use
- warm enough for Ayla and future teaching design
- no long copied book text
- always tied to source, page, and concept

## Source Note Shape

Recommended fields:

- source
- author
- source type
- concept
- source location
- printed page range
- PDF page range
- source summary
- Hearth application
- related node
- related discipline
- related level
- confidence
- extraction quality
- notes

## Confidence

Use:

- `high` - text is clear, source location is exact, interpretation is straightforward
- `medium` - source is clear but mapping/application needs review
- `low` - OCR/scan/source is uncertain or interpretation needs human checking

## Extraction Quality

Use:

- `text-good`
- `text-partial`
- `ocr-needed`
- `ocr-rough`
- `visual-review-needed`

## Rule

The source note is not the final lesson.

The source note is the bridge between the book and the final Hearth-voice content.
